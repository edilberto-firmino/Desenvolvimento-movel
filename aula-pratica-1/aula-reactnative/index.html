01 · Objetivo da aula e conceitos

Construir e executar uma lista de tarefas com React Native e Expo. O aluno poderá adicionar, concluir, excluir e recuperar tarefas salvas no aparelho.

TecnologiaResponsabilidade
ReactComponentes, propriedades e estado da interface.
React NativeComponentes de interface que usam recursos das plataformas móveis.
ExpoFerramentas, bibliotecas e serviços para desenvolver e distribuir apps React Native.
Expo GoAplicativo de aprendizado que abre projetos compatíveis a partir do servidor de desenvolvimento.
MetroEmpacota e entrega o código JavaScript durante o desenvolvimento.
Ao contrário da aula de Capacitor, a interface desta aula usa View, Text e TextInput. Não criamos index.html ou style.css para a tela nativa. O código JSX fica em arquivos JavaScript e os estilos usam objetos.

Caminho principal: computador + Node.js + editor + celular Android com Expo Go. Android Studio é opcional nesse caminho. Use o emulador se não houver celular disponível.

03 · Prepare o Expo Go e confira o SDK

  1. No Android, instale Expo Go pela loja ou pelo download oficial indicado em expo.dev/go.
  2. Depois de criar o projeto na próxima etapa, confira a versão da dependência expo em package.json.
  3. O SDK do projeto deve ser compatível com o Expo Go instalado. Se aparecer “Project is incompatible”, obtenha a versão correspondente no site oficial.
Importante para a turma: a versão mais recente do projeto pode chegar antes da atualização do aplicativo na loja. Não suponha que instalar “o mais recente” nos dois lugares garante compatibilidade. Padronize o SDK e o Expo Go utilizados pelos alunos.

iPhone: confira a orientação atual no site do Expo. A distribuição pela App Store pode não acompanhar SDKs recentes; nesses casos, use um SDK compatível ou um build de desenvolvimento. Algumas versões exigem login no Expo CLI e no Expo Go com a mesma conta. A compilação local e o simulador de iOS exigem macOS e Xcode.

07 · Código completo de App.js

useState mantém os dados da interface e useEffect carrega e salva a lista. O botão fica desativado enquanto os dados iniciais são lidos, evitando sobrescrevê-los.

App.js
import { useEffect, useRef, useState } from 'react';
import {
  FlatList, Keyboard, KeyboardAvoidingView,
  Platform, Pressable, Text, TextInput, View,
} from 'react-native';
import { StatusBar } from 'expo-status-bar';
import { SafeAreaProvider, SafeAreaView } from 'react-native-safe-area-context';
import AsyncStorage from '@react-native-async-storage/async-storage';
import Tarefa from './components/Tarefa';
import styles from './styles';

const CHAVE = '@aula-mobile:tarefas';

export default function App() {
  const [texto, setTexto] = useState('');
  const [tarefas, setTarefas] = useState([]);
  const [carregando, setCarregando] = useState(true);
  const [podeSalvar, setPodeSalvar] = useState(false);
  const [erro, setErro] = useState('');
  const proximoId = useRef(0);
  const filaDeSalvamento = useRef(Promise.resolve());

  // Carrega os dados uma vez, antes de permitir alterações.
  useEffect(() => {
    let ativo = true;
    async function carregar() {
      try {
        const salvo = await AsyncStorage.getItem(CHAVE);
        const dados = salvo ? JSON.parse(salvo) : [];
        if (!Array.isArray(dados)) throw new Error('Lista inválida');
        const validas = dados.filter(t =>
          t && typeof t.id === 'string' &&
          typeof t.texto === 'string' && typeof t.concluida === 'boolean'
        );
        if (ativo) {
          setTarefas(validas);
          setPodeSalvar(true);
        }
      } catch {
        if (ativo) setErro('Não foi possível ler os dados. A lista ficará temporária nesta sessão.');
      } finally {
        if (ativo) setCarregando(false);
      }
    }
    carregar();
    return () => { ativo = false; };
  }, []);

  // Espera o carregamento; salva alterações na ordem em que ocorreram.
  useEffect(() => {
    if (carregando || !podeSalvar) return;
    const dados = JSON.stringify(tarefas);
    filaDeSalvamento.current = filaDeSalvamento.current
      .then(() => AsyncStorage.setItem(CHAVE, dados))
      .catch(() => setErro('Não foi possível salvar a última alteração.'));
  }, [tarefas, carregando, podeSalvar]);

  function adicionar() {
    const valor = texto.trim();
    if (!valor || carregando) return;
    const id = `${Date.now()}-${proximoId.current++}`;
    setTarefas(lista => [...lista, { id, texto: valor, concluida: false }]);
    setTexto('');
    Keyboard.dismiss();
  }

  function alternar(id) {
    setTarefas(lista => lista.map(t =>
      t.id === id ? { ...t, concluida: !t.concluida } : t
    ));
  }

  function excluir(id) {
    setTarefas(lista => lista.filter(t => t.id !== id));
  }

  const concluidas = tarefas.filter(t => t.concluida).length;

  return (
    <SafeAreaProvider>
      <SafeAreaView style={styles.safe}>
        <StatusBar style="dark" />
        <KeyboardAvoidingView
          style={styles.container}
          behavior={Platform.OS === 'ios' ? 'padding' : undefined}
        >
          <Text style={styles.titulo}>Minhas Tarefas</Text>
          <Text style={styles.subtitulo}>Minha primeira aplicação com React Native e Expo.</Text>
          <Text style={styles.label}>Nova tarefa</Text>
          <TextInput
            style={styles.input}
            placeholder="Ex.: estudar programação"
            placeholderTextColor="#64748b"
            accessibilityLabel="Nova tarefa"
            value={texto}
            onChangeText={setTexto}
            onSubmitEditing={adicionar}
            returnKeyType="done"
            maxLength={150}
            editable={!carregando}
          />
          <Pressable
            onPress={adicionar}
            disabled={carregando || !texto.trim()}
            accessibilityRole="button"
            style={({ pressed }) => [
              styles.botao,
              (carregando || !texto.trim() || pressed) && styles.botaoOpaco,
            ]}
          >
            <Text style={styles.textoBotao}>Adicionar tarefa</Text>
          </Pressable>
          <Text style={styles.resumo}>
            {tarefas.length} tarefa(s) • {concluidas} concluída(s)
          </Text>
          {erro ? <Text style={styles.erro} accessibilityRole="alert">{erro}</Text> : null}
          <FlatList
            style={styles.lista}
            data={tarefas}
            keyExtractor={item => item.id}
            keyboardShouldPersistTaps="handled"
            contentContainerStyle={styles.conteudoLista}
            ListEmptyComponent={
              <Text style={styles.vazio}>
                {carregando ? 'Carregando...' : 'Nenhuma tarefa cadastrada.'}
              </Text>
            }
            renderItem={({ item }) => (
              <Tarefa tarefa={item} onAlternar={alternar} onExcluir={excluir} />
            )}
          />
        </KeyboardAvoidingView>
      </SafeAreaView>
    </SafeAreaProvider>
  );
}

09 · Código completo de components/Tarefa.js

O componente recebe dados e funções por propriedades (props). Ao tocar na tarefa, solicita a alteração de estado; ao tocar em Excluir, solicita a remoção.

components/Tarefa.js
import { Pressable, Text, View } from 'react-native';
import styles from '../styles';

export default function Tarefa({ tarefa, onAlternar, onExcluir }) {
  return (
    <View style={styles.tarefa}>
      <Pressable
        style={styles.tarefaPrincipal}
        onPress={() => onAlternar(tarefa.id)}
        accessibilityRole="checkbox"
        accessibilityState={{ checked: tarefa.concluida }}
        accessibilityLabel={tarefa.texto}
      >
        <Text style={styles.marcador} accessibilityElementsHidden>
          {tarefa.concluida ? '☑' : '☐'}
        </Text>
        <Text style={[styles.textoTarefa, tarefa.concluida && styles.concluida]}>
          {tarefa.texto}
        </Text>
      </Pressable>
      <Pressable
        style={styles.excluir}
        onPress={() => onExcluir(tarefa.id)}
        accessibilityRole="button"
        accessibilityLabel={`Excluir tarefa: ${tarefa.texto}`}
      >
        <Text style={styles.textoExcluir}>Excluir</Text>
      </Pressable>
    </View>
  );
}
O botão “Baixar arquivo” entrega Tarefa.js. Coloque esse arquivo na pasta components do projeto. Os outros dois arquivos ficam na raiz.

10 · Inicie e abra no celular

Na raiz do projeto, execute:

Terminal
npx expo start
  1. Aguarde o Metro iniciar e exibir o QR code.
  2. Conecte computador e celular à mesma rede Wi-Fi.
  3. No Android, abra Expo Go e use a opção de escanear QR code disponível na sua versão.
  4. No iPhone compatível, use a câmera para abrir o QR code e siga eventuais solicitações de login.
  5. Mantenha o terminal e o servidor de desenvolvimento abertos.

Se o servidor selecionar um cliente de desenvolvimento por engano, use explicitamente:

Terminal — modo Expo Go
npx expo start --go

Se a rede da escola não permitir conexão

Interrompa com Ctrl+C e tente o túnel:

Terminal — alternativa de conexão
npx expo start --tunnel

Aceite a instalação do suporte ao túnel se o CLI solicitar. O túnel exige internet nos dois dispositivos e pode ser mais lento. Libere o Node.js no firewall para a rede privada se houver uma solicitação do sistema; não desative o firewall inteiro.

Abrir o projeto no Expo Go não gera um APK independente. Durante esta etapa, o celular executa seu projeto através do ambiente Expo Go e do servidor de desenvolvimento.

11 · Alternativa: emulador Android

  1. Baixe e instale Android Studio.
  2. Na primeira abertura, conclua o assistente e aceite as licenças do Android SDK.
  3. No SDK Manager, instale Android SDK Platform-Tools, Android Emulator e uma plataforma Android adequada. Os nomes de menus podem variar.
  4. No Device Manager, escolha Create Device, selecione um modelo e baixe uma imagem de sistema compatível com o Expo Go.
  5. Inicie o dispositivo virtual. Confira suporte à virtualização no computador.
  6. Se o terminal não encontrar o SDK ou adb, configure as variáveis indicadas abaixo.
  7. Execute npx expo start e pressione a no terminal para abrir no Android.

Configuração no Windows

Copie o caminho real mostrado em SDK Manager → Android SDK Location. Nas variáveis de ambiente do usuário:

VariávelValor
ANDROID_HOMECaminho do SDK. Exemplo comum: C:\Users\SEU_USUARIO\AppData\Local\Android\Sdk.
PathAdicione %ANDROID_HOME%\platform-tools e %ANDROID_HOME%\emulator como entradas separadas.

Feche e reabra o terminal e o VS Code. Confira:

Terminal
adb --version
adb devices

O dispositivo virtual iniciado deve aparecer na lista. Em macOS/Linux, configure ANDROID_HOME com o caminho real do SDK e adicione platform-tools e emulator ao PATH no arquivo de configuração do seu shell. Veja o guia oficial do emulador para o seu sistema.

12 · Alternativa: executar no navegador

Para conferir a interface mesmo sem celular ou emulador, instale o suporte web na raiz do projeto:

Terminal
npx expo install react-dom react-native-web @expo/metro-runtime
npx expo start --web

Também pode iniciar com npx expo start e pressionar w. O navegador ajuda a testar o exemplo, mas o teste final mobile deve ocorrer no aparelho ou emulador.

O armazenamento no navegador é separado do armazenamento no celular. Não espere ver automaticamente as mesmas tarefas em todos os dispositivos.

13 · Edite, atualize e valide

  1. Com o projeto aberto no celular, altere o título em App.js.
  2. Salve o arquivo. O Fast Refresh atualiza a tela durante o desenvolvimento.
  3. Se a atualização não aparecer, pressione r no terminal do Expo para recarregar.
  4. Adicione três tarefas, conclua uma e exclua outra.
  5. Espere um instante para o salvamento terminar, recarregue e confira a lista restante.
  6. Confira teclado, rolagem, textos longos e áreas da barra do sistema.

Para parar o servidor, pressione Ctrl+C. Em outro dia, abra a pasta do projeto e execute novamente npx expo start. Para um projeto baixado sem node_modules, execute npm install primeiro.

Nesta aula não existe npx cap sync. O Expo entrega as mudanças de JavaScript pelo servidor. Bibliotecas nativas não presentes no Expo Go exigem um build de desenvolvimento com os módulos correspondentes.

As tarefas são dados locais, sem sincronização com servidor. AsyncStorage não é criptografado e não deve armazenar senhas. Limpar os dados do aplicativo pode remover a lista.

15 · Opcional: gere um APK independente

Faça esta etapa depois que o projeto funcionar. Um APK de preview pode ser instalado no Android e executado sem o Expo Go ou Metro. O exemplo salva dados localmente e funciona offline depois de instalado.

Prepare a conta e o projeto

  1. Crie uma conta em expo.dev.
  2. Na raiz do projeto, execute os comandos abaixo.
  3. Faça login e aceite vincular/criar o projeto Expo quando solicitado.
Terminal
npx eas-cli@latest login
npx eas-cli@latest build:configure

Selecione Android quando solicitado. A ferramenta gera eas.json e pode acrescentar configurações ao projeto.

Configure o identificador Android

No app.json, dentro de expo, defina android.package. Mescle esse trecho com o arquivo existente, preservando as demais propriedades e os metadados criados pelo EAS:

Trecho de app.json — mesclar, não substituir
{
  "expo": {
    "name": "Minhas Tarefas",
    "slug": "minhas-tarefas-expo",
    "android": {
      "package": "br.com.exemplo.minhastarefas"
    }
  }
}

Use um identificador próprio para seu projeto. Evite acentos, espaços e hífens no nome do pacote Android.

Adicione um perfil de preview

No eas.json, adicione ou ajuste build.preview. Preserve outros perfis que já existam. Para um arquivo contendo apenas esse perfil, o conteúdo é:

eas.json — perfil de APK
{
  "build": {
    "preview": {
      "distribution": "internal",
      "android": {
        "buildType": "apk"
      }
    }
  }
}

Inicie a compilação em nuvem:

Terminal
npx eas-cli@latest build --platform android --profile preview
  1. Se solicitado, permita que o EAS gere um keystore para este projeto de aula; ele será usado para assinar o aplicativo.
  2. Aguarde a fila e a compilação. O tempo e a disponibilidade dependem do plano e dos limites do serviço; consulte o painel antes da aula.
  3. Abra o link do build concluído no aparelho Android e baixe o APK.
  4. Permita a instalação pela origem utilizada quando o Android solicitar e instale o app.
  5. Abra o app, adicione uma tarefa e teste novamente sem o servidor Metro.
Esse build em nuvem não exige Android Studio no seu computador. APK de preview é para testes e distribuição direta; publicação na Google Play normalmente usa AAB e envolve conta de desenvolvedor e requisitos da loja.

Depois de alterar o código, gere um novo APK para atualizar esse build de preview. O Fast Refresh funciona no desenvolvimento, não em um APK de preview já instalado.

16 · Quando usar um build de desenvolvimento

Expo Go contém um conjunto pré-definido de módulos nativos. Quando seu projeto precisa de código nativo ou de bibliotecas fora desse conjunto, crie um cliente de desenvolvimento próprio. Para esta aula, Expo Go é suficiente.

Após configurar a conta e o projeto EAS na etapa anterior:

Terminal
npx expo install expo-dev-client

Adicione este perfil em build no eas.json, preservando preview:

Trecho de eas.json — build.development
{
  "developmentClient": true,
  "distribution": "internal"
}

O trecho acima é o valor de build.development, e não um arquivo completo. Em seguida:

Terminal
npx eas-cli@latest build --platform android --profile development
